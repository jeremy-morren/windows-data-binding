### Source generator

See README.md for a rough overview. Note the following rules:

- See https://github.com/dotnet/roslyn/blob/main/docs/features/incremental-generators.cookbook.md for the official cookbook for source generators.
- At top of file, add `// <auto-generated>` and a note to indicate that the file is auto-generated.
- At top of file, add `// ReSharper disable all` to disable ReSharper warnings for the file.
- Apply `System.CodeDom.Compiler.GeneratedCodeAttribute` to the generated class.
- Enable nullability in the generated file, disable analysis: `#nullable enable annotations + #nullable disable warnings`
- `GenerateWindowsBindingModelAttribute` is the entrypoint: look for this attribute on a class to kick off source generation.
- Setup nuget package (private assets, shipped attribute, etc) the same as `StronglyTypedId` source generator (look on github)

- Fully qualified everywhere: emitted type names use `global::`, and XML doc `cref`s are namespace-qualified,
  so nothing in the generated file can be captured by a name in the consuming project.
- Property chain is prefixed with `_`
- Include: public properties (init and get-only), public fields.
- Ensure that if the target type is partial, all parts are considered.
- Circular references are not allowed (i.e. a type found twice in a property chain). If a circular reference is detected, the property should be skipped and a warning should be logged.
- No max depth limit, thousands of properties are supported.
- Property is not nullable only if it can be statically proven to be non-nullable. Ignore nullable annotations. No property should throw a null reference exception at runtime.
- summary XML comment should be the exact code generated for the property, without the _source prefix (i.e. copy-paste the code generated for the property into the summary comment).
- Remarks should be a chain of `<see cref="PropertyName"/>` for each property in the chain, starting from the root property and ending with the current property.
- For deep properties that require a check (i.e. `Interval`), do: `Property?.Interval.HasStart == true ? Property.Interval.Start.ToDateTimeUtc() : null`
- Join summary property remarks together by `: ` and apply to `[DescriptionAttribute]` for the property. If none of the properties have a summary remark, skip.
- For types with multiple properties, add `(MemberSuffix)` to the description (see readme example). If none of the properties has a summary remark, ignore as before.
- IDE performance is key: use Incremental generator to its fullest potential.
- Keep code clean: terse comments, helper methods and classes wherever possible.
- Source generator is targeted for .NET 2.0 as per docs.
- Recognise types just by their namespace i.e. assume that a type called `NodaTime.Instant` is that type 
  (see system.text.json source generation in dotnet/runtime repository for what is presumably the best way to do this)
- These are read-only models (for displaying data). No INotifyPropertyChanged support.
- Tests: use testing packages from cookbook above and XUnit verify. See again System.Text.Json for inspiration.
- Tests: use the string assertions strategy: define expectation inline in the test. 
  For each test: generate source, assert no compilation errors, match expected output, if any diagnostics were expected, check those exist.
- Ensure the NETstandard2.0 output is tested somehow i.e. that both code paths are compiled.
- Name collections: If class has property `Address_Street` and `Address.Street`: 1st come 1st served i.e. use the order the properties are declared in.
  Create a data structure for this (immutable, use `ImmutableList<string>` internally, 
  with a static method for generating path that takes a list and an index,
  and generates path for chain at that index on a first-come-first-served basis)
- `IEnumerable<>`: Properties can only be a closed type i.e. property type will actually be `List<int>`. 
- Constructor should have same visibility as the source class
- No generic types: diagnostic if any generic type encountered.
- Diagnostics: report when attribute applied to non-partial class.
- Supported nested classes, diagnostic when parent class is non-partial
- All diagnostics from this source generator, not a separate analyzer (ignore cookbook here).

`DateOnly` properties should be as follows (Description attribute is placeholder):

```csharp
#if NET6_0_OR_GREATER
	/// <summary><c>PropertyName.ToDateOnly()</c></summary>
#else
	/// <summary><c>PropertyName.ToDateTimeUnspecified()</c></summary>
#endif
	/* Remarks and description here, same for both */
#if NET6_0_OR_GREATER
	public DateOnly PropertyName => _source.PropertyName.ToDateOnly();
#else
	public DateTime PropertyName => _source.PropertyName.ToDateTimeUnspecified();
#endif
```
